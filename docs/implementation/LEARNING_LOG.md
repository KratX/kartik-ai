### 1. Concept learned
- **Pluggable `HttpTransport` Enables Zero-Backend Interactive Portfolio Demos (`Blueprint §12`):**
  - Because `KartikGatewayClient` (`@kartik/frontend/lib/api-client`) accepts an injected `HttpTransport`, `createInteractiveDemoHarness()` can simulate the entire API Gateway (`/api/v1/*`) in browser memory while still exercising the real `KartikWorkspaceShellController`, `WorkspaceStore`, `BillingCheckoutController`, `validateClientUploadCandidate`, `formatGroundedCitations`, and `buildSandboxedPreviewDocument` code paths.

## Entry 34 — Phase 9 / Step 9.1 (Micro-step 9.1.a): Canonical 7-Agent Contract (`pdf` & `ppt`) & Standards-Compliant Binary PDF / PPTX Builders

### 1. Concept learned
- **Schema-First Binary Artifact Generation (`Blueprint §7.2 Phase 10 & Invariant #12`):**
  - Instead of asking an LLM to emit raw binary or unvalidated markup, the PDF and PPT agents enforce a two-step pipeline:
    1. Validate and sanitize untrusted JSON against `validatePdfDocumentSpec` / `validatePptPresentationSpec` (enforcing length ceilings so oversized inputs truncate predictably rather than corrupting the file).
    2. Deterministically compile the validated specification into a standards-compliant `%PDF-1.4` binary (`buildPdfBinaryBuffer`, complete with `Catalog`, `Pages`, `Page` content streams, page numbering, `"Generated by Kartik.ai"` footer, and exact byte-offset `xref` table) or an OpenXML `.pptx` ZIP container (`buildPptxBinaryBuffer`, `PK\x03\x04` with `[Content_Types].xml`, `ppt/presentation.xml`, and DrawingML slide XMLs for the Cover, 6 Content Slides, and Thank You Slide).

### 2. What was implemented
- Expanded `AGENT_NAMES`, `SPECIALIST_AGENT_NAMES`, and `BILLING_OPERATIONS` in `@kartik/shared/contracts`, `@kartik/billing`, `@kartik/chat`, and `@kartik/frontend` to include `pdf` (`pdf_generation`) and `ppt` (`ppt_generation`).
- Created `backend/services/agent/src/schemas/index.ts`, `backend/services/agent/src/agents/pdf/index.ts`, `backend/services/agent/src/agents/ppt/index.ts`, and `backend/services/agent/tests/pdf-ppt-generators.test.ts` (`5/5` tests passing).

## Entry 35 — Phase 9 / Step 9.2 (Micro-step 9.2.a): Live Server-Side `@google/genai` Providers, 2-Stage Coding Intent Classifier, Real Binary PDF Loader & Per-Agent Sliding-Window Rate Limiter

### 1. Concept learned
- **Two-Stage Coding Intent Classification (`Blueprint §4.1 & Tutorial Part 2`):**
  - Not every coding prompt wants a brand-new multi-file web app that overwrites the user's Artifact workspace. By classifying prompts first (`classifyCodingIntent` → `CODE_GENERATION` vs `CODE_REVIEW`, `CODE_EXPLANATION`, `DEBUGGING`, `OPTIMIZATION`), `AgentGraphExecutor` only generates a `code_bundle` artifact on `CODE_GENERATION` and returns rich syntax-highlighted Markdown inline in the chat bubble for code reviews, debugging, and explanations.
- **Per-Agent Sliding-Window Rate Limiting (`Blueprint §9.4, §12 & §15.1`):**
  - `AgentSlidingWindowRateLimiter.checkAgentLimit` enforces granular per-user, per-minute quotas (`chat: 20/min`, `coding/pdf/ppt/rag/vision/image/search: 5/min`) using scoped Redis keys (`rl:{agent}:{userId}:{minuteBucket}`) and returns `429 RATE_LIMITED` with an exact `retryAfterSeconds` countdown.
- **Zero-Dependency PDF Binary Text Extraction (`extractTextPagesFromPdfBytes`):**
  - Parses `%PDF-1.x` content streams (including `FlateDecode` zlib-compressed streams and PDF text operators `Tj`/`TJ`) directly into `{ pageNumber, text }[]` so uploaded `.pdf` files are chunked and vector-indexed automatically without external native binaries.

### 2. What was implemented
- `backend/services/agent/src/services/agent-rate-limiter.ts`
- `backend/services/agent/src/rag/loaders/index.ts` & `backend/services/agent/src/rag/index.ts`
- `backend/services/agent/src/agents/coding/index.ts` & `backend/services/agent/src/graph/index.ts`
- `backend/services/agent/src/services/live-gemini-providers.ts`

## Entry 36 — Phase 9 / Step 9.3 (Micro-step 9.3.a): Full-Stack Express + Vite Server (`server.ts` on Port 3000), Binary File Upload (`/files/upload`) & Artifact Content Streaming (`/artifacts/:id/content` & `/raw`)

### 1. Concept learned
- **Ownership-Verified Binary Streaming vs. JSON Metadata (`Blueprint Invariants #10 & #20`):**
  - Private objects (`%PDF-1.4` documents, OpenXML `.pptx` slide decks, `.png` images, and multi-file code bundles) are never stored in public buckets.
  - `GET /api/v1/artifacts/:artifactId/content` verifies ownership via `FileIngestionAndArtifactService.getArtifactWithRawBytes` (returning `404 NOT_FOUND` on missing or foreign-owned artifacts) and delivers both the signed URL and Base64 payload, while `GET /api/v1/artifacts/:artifactId/raw` streams the raw binary buffer with `Content-Disposition: attachment; filename="..."` for instant 1-click browser downloads.

### 2. What was implemented
- `backend/shared/storage/index.ts` (`getPrivateObject` on `ObjectStorage` and `InMemoryObjectStorage`)
- `backend/services/agent/src/rag/index.ts` (`getArtifactWithRawBytes`)

- `src/server/platform-api-runtime.ts` & `server.ts` (Port 3000 Express + Vite full-stack server)
- `backend/services/agent/tests/artifact-content-and-upload-routes.test.ts` (`2/2` tests passing)
